# Glee-fully Tools deployment contract

This repository is the source of truth for the public site at
[glee-fully.tools](https://glee-fully.tools).

## Publishing source

- **Source branch:** `main`
- **Trigger:** a push to `main`, or a maintainer-run `workflow_dispatch`
- **Workflow:** [`.github/workflows/deploy-pages.yml`](../.github/workflows/deploy-pages.yml)
- **Pages mode:** GitHub Actions workflow publishing (not legacy branch publishing)
- **Validated commit:** the deploy job checks out the exact commit that passed its preceding validation job in the same workflow run.

## Artifact and paths

The site is plain static HTML. The Pages artifact is the repository root (`path: .`)
so the deployed artifact must contain the root [`index.html`](../index.html),
`assets/`, each public route directory, and the generated data files. No bundler,
framework build, or alternate output directory is introduced by deployment.

The site is served at the domain root. Internal links and asset references therefore
remain root-relative or resolve from each existing page directory as authored. The
workflow does not add a base-path prefix, rewrite routes, or transform HTML; direct
routes such as `/about/`, `/legal/`, and toolbox pages are deployed from the same
directory structure committed here.

## Custom domain

`CNAME` is committed at the artifact root and must contain exactly:

`glee-fully.tools`

The workflow verifies that value before upload. GitHub Pages custom-domain and HTTPS
settings remain attached to `glee-fully.tools`; a deployment must not replace the
CNAME with a preview or repository URL. The CNAME is intentionally not generated by
CI, so domain drift is reviewable in pull requests.

## Release guardrails

The deploy job runs the same content/index/link/contrast validation used by the
repository validation workflow before uploading anything. A failed validation means
no Pages artifact is uploaded and no deployment is attempted. Visual content,
navigation, and brand tokens are not changed by this handoff.
